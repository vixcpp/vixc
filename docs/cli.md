# Vix++ CLI

The Vix++ CLI is exposed through the `vix++` command.

It reads `.vix` files, transpiles them to standard C++, then delegates the build or execution to the existing `vix` CLI.

## Relationship with Vix

Vix++ does not replace Vix.

```txt
vix     -> runtime and build engine for standard C++
vix++   -> language frontend for .vix files
```

The pipeline is:

```txt
main.vix
  ↓
vix++ transpiler
  ↓
.vix/build/vixpp/main.generated.cpp
  ↓
vix run/build/check
  ↓
binary
```

This means `vix++` needs the `vix` command to be installed and available in `PATH`.

## Usage

```sh
vix++ <command> <file.vix> [options]
```

Available commands: `run`, `build`, `check`, `help`, `version`.

## Run

```sh
vix++ run main.vix
```

This transpiles `main.vix` into `.vix/build/vixpp/main.generated.cpp`, then delegates to:

```sh
vix run .vix/build/vixpp/main.generated.cpp
```

Shortcut:

```sh
vix++ main.vix
```

This is equivalent to `vix++ run main.vix`.

## Build

```sh
vix++ build main.vix
```

This transpiles the `.vix` file and delegates to:

```sh
vix build .vix/build/vixpp/main.generated.cpp
```

You can forward Vix build options:

```sh
vix++ build main.vix --out app
```

Internally, this becomes:

```sh
vix build .vix/build/vixpp/main.generated.cpp --out app
```

## Check

```sh
vix++ check main.vix
```

This transpiles the `.vix` file and delegates to:

```sh
vix check .vix/build/vixpp/main.generated.cpp
```

## Help

```sh
vix++ help
```

Aliases: `vix++ -h`, `vix++ --help`

## Version

```sh
vix++ version
```

Aliases: `vix++ -v`, `vix++ --version`

## Options

### `--vix`

Use a custom path to the `vix` binary:

```sh
vix++ run main.vix --vix /usr/local/bin/vix
```

Default: `vix`

### `--build-dir`

Change where generated C++ files are written:

```sh
vix++ run main.vix --build-dir .vix/generated
```

Default: `.vix/build/vixpp`

## Forwarded arguments

Any argument that is not a Vix++ option is forwarded to Vix after the generated file.

Example:

```sh
vix++ build main.vix --out app
```

Delegates to:

```sh
vix build .vix/build/vixpp/main.generated.cpp --out app
```

You can also use `--` to explicitly forward the remaining arguments:

```sh
vix++ run main.vix -- --port 8080
```

Delegates to:

```sh
vix run .vix/build/vixpp/main.generated.cpp --port 8080
```

## Generated files

For this command:

```sh
vix++ run examples/hello.vix
```

Vix++ writes:

```txt
.vix/build/vixpp/hello.generated.cpp
```

The generated file starts with:

```cpp
// Generated by Vix++. Do not edit directly.
```

Then the resolved includes are emitted before the copied C++ body.

### Example

Input:

```cpp
use std.iostream;

int main()
{
  std::cout << "Hello from Vix++\n";
  return 0;
}
```

Generated C++:

```cpp
// Generated by Vix++. Do not edit directly.
#include <iostream>

int main()
{
  std::cout << "Hello from Vix++\n";
  return 0;
}
```

Command:

```sh
vix++ run examples/hello.vix
```

## Error cases

### Missing input file

```sh
vix++ run
```

Output:

```txt
vix++: error: missing input file
run 'vix++ help' for usage.
```

### Invalid file extension

```sh
vix++ run main.cpp
```

Output:

```txt
main.cpp: error: expected a .vix source file
hint: Vix++ source files must use the .vix extension
```

### Import after code

```cpp
int main()
{
  return 0;
}

use vix.core;
```

Output:

```txt
main.vix:6:1: error: import declarations must appear before regular C++ code
hint: move this use declaration to the top of the file
```

### Missing Vix binary

If `vix` is not installed or not available in `PATH`, the delegated command fails. Use:

```sh
vix++ run main.vix --vix /path/to/vix
```

## Current behavior

The MVP CLI is intentionally small. It does:

- load `.vix` file
- resolve `use` imports
- generate `.cpp` file
- call `vix`
- return `vix` exit code

It does not yet do:

- install Vix automatically
- manage Vix packages
- parse project metadata
- watch files
- format `.vix` files
- run a Vix++ REPL

Those features can be added later while keeping the first CLI stable.

## Design rule

`vix++` should stay focused.

```txt
vix++ handles the language layer.
vix handles the build and runtime layer.
```
